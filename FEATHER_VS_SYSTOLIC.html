FEATHER vs. Systolic

See how shape, mapping, and layout affect the work that reaches each PE.

Follow the same operands through a 16×16 systolic array and a 16×16 FEATHER NEST. Start with 1×12×32 (M×K×N), then follow a connected chain whose output becomes the next layer’s input.

A transparent teaching model, not a hardware benchmark. The clock counts simplified logical issue, propagation, reduction, and drain steps. Weights are assumed available, memory stalls and actual FP16 pipeline/control delays are not modeled. Compare the assumptions below before reading a cycle difference as an architectural advantage.

03 / PRODUCER → CONSUMER

Layout switching is a separate question

Architectural what-if

A producer’s output order may differ from the next mapping’s input order. Watch the same output coordinates change bank/slot assignment below. A matching layout has zero additional repack traffic. Baseline assumptions and any copy cost are explicit, not hidden inside MAC utilization.

Bank cells illustrate MINISA whole-tensor rank orders, not the allocation of a currently resident RTL tile. For a one-row tensor, different rank orders can collapse to the same addresses. Try the short-batch chain to see a nontrivial producer–consumer permutation.

Capability boundary: FEATHER’s architectural dataflow/layout flexibility motivates this what-if. The current FP16 RTL path is weight-oriented: this page’s implemented-mode comparison varies spatial mapping and partitioning, not an unsupported runtime dataflow switch. Reduction–reordering (RIR), producer-to-consumer on-chip reuse, and avoiding materialization are architectural illustrations, not verified capabilities of the current MINISA FP16 runtime.

What this comparison does—and does not—claim

Equal work, visible mapping

Both sides have 256 PEs and perform identical mathematical GEMMs. Equal PE counts do not imply equal area, storage, wiring cost, or clock frequency. No batch fusion or independent request packing is credited. Inactive edge coordinates do no useful MACs. The selected baseline determines which two GEMM dimensions occupy the systolic grid.

Logical clocks, not measurements

Animations count useful MAC events and model-specific propagation/reduction/drain overhead. They omit DMA/off-chip traffic, WS/IS partial-sum spill traffic, buffer capacity, clock frequency, physical timing, energy, and common resident-weight loading. Layout costs are editable illustrative estimates, not benchmark data.

Spatial occupancy is not throughput

For 1×12×32, FEATHER expands N ownership across rows and columns; K=12 is not split. Other mappings can partition K and use BIRRD to combine partials. A wavefront, output contention, reduction, or setup can still limit instantaneous or average utilization. More mapped PEs alone is not a speedup claim.
