The layouts feeding those PEs

A layout defines how 16-element vectors occupy 16 SRAM banks. The window below follows the selected PE; its vector is outlined. Layout order and tile extent together determine the address.

For vector index L: bank = L mod 16; scalar row = 16⌊L/16⌋ + lane. Weight/input vectors run along K; output vectors run along N. Buffer depths are StaB/StrB/OB = 128/64/64 scalar rows per bank.

Exact commands, numerical samples, and model boundaries

The inference graph follows the recorded logits_to_keep=1 workload. Residual addition, normalization, row selection, sampling, embedding and boundary repacking are shown as graph context; their execution costs are excluded from the GEMM predictions. The display does not assume an automatic output-buffer-to-input-buffer handoff.

Each operation loads its own weights. The preceding operation supplies the mapping to consider retaining. The mapper performs a bounded tile/layout search, not a proof of global optimality or a graph-wide layout-cost optimization. The selected A/B descriptors match its winner; eight-replica and wider candidates make the alternatives explicit.

Predictions use serialized_minisa_v2, including operand loads, PE preload, stream, gaps/drain, dispatch and stores. No new RTL measurements are claimed. Values in the PE inspector are synthetic teaching samples; tensor names and graph dependencies are symbolic, not a full numerical inference replay.
